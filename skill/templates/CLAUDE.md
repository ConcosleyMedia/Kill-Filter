## Hard rules for the build

1. **Plan before you write.** For every feature, write the plan in `spec.md` first. No code without a plan.
2. **One feature at a time.** Finish a feature end-to-end (UI + API + data + tested) before starting the next.
3. **Read before writing.** Before modifying a file, read the entire file. Before adding a feature, read `spec.md` and `cut-list.md` to confirm it's in scope.
4. **Verify before declaring done.** A feature is done when it works in the deployed environment, not when the local build compiles.
5. **Stop when blocked.** If you hit auth, Stripe, or deploy issues for >30 minutes, stop and ask the user. These are the three named walls.
6. **Never build something on the cut list.** The cut list is in `cut-list.md`. If a feature is on it, do not build it. Do not "add it just in case." Do not refactor toward it.
