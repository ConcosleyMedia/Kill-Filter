## What this stack is not

- Not a microservices architecture. One Next.js app, one database. That's it.
- Not multi-region. One Vercel deploy, one Supabase project.
- Not multi-tenant in the SaaS sense. Each user has their own data; that's it. No team accounts in v1 (cut).

## The three walls (and how to skip them)

These three things kill 90% of vibe-coded apps. Address each before you hit it:

1. **Supabase auth callback URL.** Set the redirect URL in Supabase project settings AND in your `lib/supabase/client.ts`. Local dev uses `http://localhost:3000`; production uses your custom domain. Both must be added to the allow-list.

2. **Stripe webhook signature verification.** Webhook events MUST verify the signature server-side using `stripe.webhooks.constructEvent`. Use the raw request body, not the parsed JSON. Vercel's API routes default to JSON-parsing the body — disable it for the webhook route.

3. **Vercel deploy.** Push to main triggers deploy. Custom domain takes 2 minutes after DNS propagates. Add `NEXT_PUBLIC_APP_URL` env var so absolute URLs work in production.

The Wall-Skip Kit (Build Room paid tier) has working code for all three. If you're stuck >30 minutes on any of these, ask in the Build Room chat — these are not problems worth grinding alone.

## What's not in this stack

- No Redis. Postgres is fine for v1 caching.
- No queues. Vercel cron + a Postgres jobs table covers anything you'll actually need.
- No Docker. Vercel handles deploys. Don't introduce containers until you need to.
- No analytics tool. Plausible or Posthog can come post-launch. v1 instruments via console logs and Vercel logs.
